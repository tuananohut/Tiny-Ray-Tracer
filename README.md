# Tiny Ray Tracer in C++

![image](https://github.com/tuananohut/Tiny-Ray-Tracer/assets/57767763/9a33f91f-bf48-462f-8290-12155ee65fbf)

A minimalist, from-scratch implementation of a ray tracer in C++. This project was undertaken as a deep dive into the fundamentals of photorealistic rendering, shifting focus from the real-time rasterization techniques of OpenGL/DirectX to the physically-based simulation of light transport.

---

## Project Overview

The goal of this project was to build a complete understanding of how realistic images are synthesized by simulating the physics of light. Unlike rasterization, which projects 3D geometry onto a 2D screen, this ray tracer simulates individual rays of light as they travel from a virtual camera, bounce off surfaces in a scene, and accumulate color to produce a final image. It is a study in first principles, designed to build an intuition for the algorithms that power modern high-fidelity graphics.

---

## Key Features & Implemented Concepts

* **Ray Generation:** For each pixel on the screen, a primary ray is cast from the camera into the 3D scene.
* **Ray-Sphere Intersection:** Mathematical algorithms to accurately determine if a ray intersects with the spheres in the scene, and if so, where.
* **Shading & Materials:** Implementation of a simple lighting model to calculate the color of a surface based on its material properties (e.g., diffuse color) and its interaction with light sources.
* **Recursive Reflections:** To achieve realistic reflections, secondary rays are cast from the intersection point in the reflection direction. This recursive process allows for objects to reflect each other multiple times, creating depth and realism.
* **Shadows:** Before shading a point, "shadow rays" are cast from the intersection point towards each light source. If a shadow ray hits another object before reaching the light, the point is considered to be in shadow.

## What I Learned: A New Way of Thinking About Graphics

Building a ray tracer required a fundamental shift in my mental model of rendering.

* **From Polygons to Rays:** The biggest shift was moving from the "all at once" approach of a rasterizer's rendering pipeline to the "one pixel at a time" query-based nature of ray tracing. It taught me to think of rendering as a problem of information gathering rather than projection.

* **Vector Math is Everything:** This project was a masterclass in the practical application of vector mathematics. Concepts that were previously abstract became concrete tools:
    * **Dot Product:** Used everywhere, from calculating the angle of light hitting a surface (for diffuse shading) to determining ray-plane intersections.
    * **Vector Reflection:** Used to calculate the direction of reflected rays.

## How to Build & Run

This project uses CMake for a simple, cross-platform build process.

1.  **Clone the Repository:**
    ```bash
    git clone https://github.com/tuananohut/Tiny-Ray-Tracer.git
    cd Tiny-Ray-Tracer
    ```
2.  **Create a Build Directory:**
    ```bash
    mkdir build && cd build
    ```
3.  **Configure and Build with CMake:**
    ```bash
    cmake ..
    make
    ```
4.  **Run the Executable:**
    ```bash
    ./tinyraytracer
    ```
    The program will generate an `out.ppm` image file in the build directory.
